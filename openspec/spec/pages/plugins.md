# 插件管理规格

> 依据「插件管理.png」「插件管理-安装新插件.png」「插件管理「历史」.png」
> 以及 DESIGN.md §6.2 的批量更新实证

## 结构

1. **工具栏**：`N 个已安装` + 「+ 安装新插件」
2. **开关区**：自动安装依赖 / 放心装（右侧批量操作 4 个）
3. **搜索框**：搜索插件名称、地址
4. **插件卡片列表**

## 开关

| 开关 | 状态托管 |
|---|---|
| 自动安装依赖 | App 的 `autoInstall` |
| 放心装 | App 的 `safeMode` |

与内核管理页的「自动安装依赖」**共享同一状态**。

## 批量操作（4 种，共用 BatchModal）

| 模式 | 说明 | 底部按钮 |
|---|---|---|
| `export` | 导出所选插件配置 | 立即执行 (N) |
| `update` | 更新所选插件 | 立即执行 (N) |
| `toggle` | 切换启用状态 | 立即执行 (N) |
| `uninstall` | 卸载所选插件（danger） | 立即执行 (N) |

打开时默认全选，提供分组全选/取消。
`update` 模式额外提供「仅显示当前有新版本的插件」复选框（截图实证），
勾选后仅列出 `hasUpdate === true` 的插件，
全部为最新时显示「没有有新版本的插件」空态。

执行后：终端输出每项的日志 + Toast 汇总。

## 行内操作（4 个，均有二次确认）

| 按钮 | 行为 |
|---|---|
| 最新 | 拉取最新版本，Toast「回滚成功（无需安装依赖）」 |
| 历史 | 打开 HistoryModal |
| 启用/禁用 | `ConfirmModal` 确认后切换 |
| 卸载 | `ConfirmModal`（danger）确认后卸载 |

## 弹窗（4 个）

| 弹窗 | 触发 | 内容 |
|---|---|---|
| 安装新插件 | 工具栏按钮 | 仓库地址输入（空则禁用「开始安装」）+ 选择本地插件目录 |
| 历史版本 | 卡片「历史」 | 提交版本列表（空态）+ 切换到指定版本 |
| 切换版本确认 | 历史版本内切换 | `ConfirmModal`，取消 / 确认 |
| 批量操作 | 4 个批量按钮 | 见上表 |

## 空态

未搜索：`暂无已安装插件`；搜索无结果：`未找到匹配的插件`。

## 数据

`plugins=[]`（App 传入）。真实数据接入后卡片与批量列表同步渲染。
卡片字段：名称 / 仓库地址 / 已启用徽标 / 分支 / GIT 版本 / 更新时间。
